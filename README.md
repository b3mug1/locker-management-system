# Locker Management System

A full-stack, production-ready web application for managing student locker assignments. It supports role-based access control, real-time updates via WebSocket, barcode-based student lookup, inclusive-status tracking, and multi-language UI.

## Features

- **Role-based access control** — `admin` users manage everything; `user` role is restricted to read-only views of their own locker.
- **Student management** — CRUD with barcode identifier, course year, group, and inclusive/priority status (`none`, `disability`, `orphan`, `vision`, `hearing`, `other`).
- **Locker management** — Track locker number, size (`small` / `medium` / `large`), access type (`key` / `pin`), capacity (1–2 students), floor, and status (`active` / `inactive` / `maintenance`).
- **Assignment lifecycle** — Assign a locker to a student; release it when done. History is preserved with `assigned_at` / `released_at` timestamps.
- **Dashboard** — At-a-glance stats: total/available/occupied/maintenance lockers, total students, active assignments.
- **Real-time updates** — WebSocket endpoint broadcasts changes to all connected clients so dashboards update instantly.
- **JWT authentication** — Stateless Bearer token auth with configurable expiry.
- **Swagger / ReDoc docs** — Interactive API docs auto-generated by FastAPI at `/docs` and `/redoc`.
- **Multi-language UI** — Language context in the React frontend supports locale switching.
- **Email service** — Built-in SMTP integration (no extra packages — uses Python's `smtplib`).

## Architecture Overview

```
Browser
  │
  ▼
Nginx (port 3000)          ← serves React SPA, proxies /api & /ws
  │
  ├─ /api/*  ──────────►  FastAPI (port 8000)
  │                           ├── /api/v1/auth
  │                           ├── /api/v1/users
  │                           ├── /api/v1/students
  │                           ├── /api/v1/lockers
  │                           ├── /api/v1/assignments
  │                           └── /api/v1/dashboard
  │
  └─ /ws  ─────────────►  FastAPI WebSocket hub
                              │
                              ▼
                         PostgreSQL 16 (port 55432 on host)
```

The backend uses **async SQLAlchemy** with **asyncpg** for non-blocking database access. Alembic handles schema migrations automatically on startup.

## Quick Start (Docker)

```bash
# Navigate to the project root
cd locker-management-system

# Copy the example env file and adjust values if needed
cp .env.example .env   # or create .env manually (see Environment Variables below)

# Build and start all services
docker-compose up --build
```

Once running:

| Service        | URL                           |
|----------------|-------------------------------|
| Frontend (SPA) | http://localhost:3000          |
| Backend API    | http://localhost:8000          |
| Swagger UI     | http://localhost:8000/docs     |
| ReDoc          | http://localhost:8000/redoc    |
| PostgreSQL     | localhost:55432                |

Stop everything:

```bash
docker-compose down
```

Destroy volumes (wipes the database):

```bash
docker-compose down -v
```

## Environment Variables

Create a `.env` file in the project root. All variables have sensible defaults for local development.

| Variable                    | Default                                      | Description                              |
|-----------------------------|----------------------------------------------|------------------------------------------|
| `POSTGRES_USER`             | `locker_admin`                               | PostgreSQL username                      |
| `POSTGRES_PASSWORD`         | `locker_secret_2026`                         | PostgreSQL password                      |
| `POSTGRES_DB`               | `locker_db`                                  | PostgreSQL database name                 |
| `POSTGRES_HOST`             | `db`                                         | Hostname of the DB container             |
| `POSTGRES_PORT`             | `5432`                                       | Internal container port                  |
| `DATABASE_URL`              | *(derived from above)*                       | Async SQLAlchemy URL (`asyncpg`)         |
| `DATABASE_URL_SYNC`         | *(derived from above)*                       | Sync SQLAlchemy URL (Alembic)            |
| `SECRET_KEY`                | `change-me-in-production`                    | **Change this in production!**           |
| `ALGORITHM`                 | `HS256`                                      | JWT signing algorithm                    |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | `60`                                       | JWT lifetime in minutes                  |
| `BACKEND_CORS_ORIGINS`      | `["http://localhost:3000","http://localhost:5173"]` | Allowed CORS origins (JSON array)  |
| `FIRST_ADMIN_EMAIL`         | `admin@locker.com`                           | Email for the seeded admin account       |
| `FIRST_ADMIN_PASSWORD`      | `admin123`                                   | Password for the seeded admin account    |
| `SMTP_HOST`                 | `smtp.gmail.com`                             | SMTP server host                         |
| `VITE_API_URL`              | `http://localhost:8000`                      | API base URL injected at frontend build  |

> **Security note:** Always override `SECRET_KEY`, `POSTGRES_PASSWORD`, `FIRST_ADMIN_PASSWORD`, and SMTP credentials before deploying to production.

## Local Development (without Docker)

### Backend

```bash
cd backend

# Create and activate a virtual environment
python -m venv .venv
.venv\Scripts\activate   # Windows
# source .venv/bin/activate  # Linux/macOS

# Install dependencies
pip install -r requirements.txt

# Set env vars (or create a .env in the backend/ directory)
# DATABASE_URL must point to a running PostgreSQL instance

# Run migrations
alembic upgrade head

# Seed the database
python -m app.seed

# Start the dev server
uvicorn app.main:app --reload --port 8000
```

### Frontend

```bash
cd frontend

# Install dependencies
npm install

# Start the Vite dev server (proxies /api to localhost:8000)
npm run dev
```

The frontend dev server runs on **http://localhost:5173** by default.

## Database Migrations

Migrations live in `backend/alembic/versions/`. Alembic is run automatically by Docker Compose on every startup (`alembic upgrade head`).

| Migration | Description                              |
|-----------|------------------------------------------|
| `001`     | Initial schema (users, students, lockers, assignments) |
| `002`     | Add email verification fields            |
| `003`     | Drop verification fields                 |
| `004`     | Add barcode to students; link user→student |
| `005`     | Add course year to students              |
| `006`     | Add maintenance locker status            |
| `007`     | Add inclusive/priority status to students |

To generate a new migration after changing a model:

```bash
cd backend
alembic revision --autogenerate -m "describe_your_change"
alembic upgrade head
```

## Default Credentials & Seeded Data

| Role  | Email            | Password  |
|-------|------------------|-----------|
| Admin | admin@locker.com | admin123  |
| User  | user@locker.com  | user123   |

On first startup the seed script (`app/seed.py`) creates:

- 1 admin user + 1 demo regular user
- 100 students with random names, groups, courses, and barcodes (generated with Faker)
- 100 lockers (`L-001` → `L-100`) with random sizes, access types, floors, and capacities

Re-running the seed script is idempotent — it skips records that already exist.

## Data Models

### Student

| Field             | Type    | Notes                                                      |
|-------------------|---------|------------------------------------------------------------|
| `id`              | int     | Primary key                                                |
| `full_name`       | string  | Student's full name                                        |
| `group`           | string  | Class / study group                                        |
| `barcode`         | string  | Unique barcode identifier                                  |
| `course`          | int     | Academic year (1–6)                                        |
| `inclusive_status`| string  | `none` / `disability` / `orphan` / `vision` / `hearing` / `other` |

### Locker

| Field         | Type   | Notes                                    |
|---------------|--------|------------------------------------------|
| `id`          | int    | Primary key                              |
| `number`      | string | Unique locker identifier (e.g. `L-042`)  |
| `size`        | string | `small` / `medium` / `large`             |
| `access_type` | string | `key` / `pin`                            |
| `capacity`    | int    | Max concurrent students (1 or 2)         |
| `floor`       | int    | Building floor                           |
| `status`      | string | `active` / `inactive` / `maintenance`    |

### Assignment

| Field         | Type      | Notes                                    |
|---------------|-----------|------------------------------------------|
| `id`          | int       | Primary key                              |
| `student_id`  | int       | FK → students                            |
| `locker_id`   | int       | FK → lockers                             |
| `assigned_at` | timestamp | Auto-set on creation (timezone-aware)    |
| `released_at` | timestamp | Nullable; set when locker is released    |

### User

| Field      | Type   | Notes                        |
|------------|--------|------------------------------|
| `id`       | int    | Primary key                  |
| `email`    | string | Unique login email           |
| `role`     | string | `admin` / `user`             |
| `student_id` | int  | Optional FK → students       |

## Real-Time Updates

The backend exposes a WebSocket endpoint at `ws://localhost:8000/ws`. When any assignment or locker change is made through the API, the server broadcasts an event to all connected clients. The React frontend subscribes via the `useWebSocket` hook (`src/hooks/useWebSocket.js`) and refreshes the relevant page data automatically — no polling required.

## API Endpoints

### Authentication
- `POST /api/v1/auth/register` – Register new user
- `POST /api/v1/auth/login` – Login (returns JWT)

### Students (Admin)
- `GET    /api/v1/students`
- `POST   /api/v1/students`
- `GET    /api/v1/students/{id}`
- `PUT    /api/v1/students/{id}`
- `DELETE /api/v1/students/{id}`

### Lockers (Admin)
- `GET    /api/v1/lockers`
- `POST   /api/v1/lockers`
- `GET    /api/v1/lockers/{id}`
- `PUT    /api/v1/lockers/{id}`
- `DELETE /api/v1/lockers/{id}`

### Assignments (Admin)
- `GET  /api/v1/assignments`
- `POST /api/v1/assignments` – Assign locker
- `POST /api/v1/assignments/{id}/release` – Release

### User
- `GET /api/v1/assignments/my` – View own assignments
